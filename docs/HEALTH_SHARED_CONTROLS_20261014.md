## Native accessibility evidence

CI run 38492216310 / job 115619854895 exposed the visible disabled button. Installed native GeolocateControl reproduces its HTML exactly while the permission-support promise remains pending:

```html
<button class="maplibregl-ctrl-geolocate" type="button" disabled="">
  <span class="maplibregl-ctrl-icon" aria-hidden="true"></span>
</button>
```

`src/lib/map-geolocation.ts` supplies title and aria-label in the public native onAdd boundary without enabling the button. English initial name is Find my location; Spanish is Buscar mi ubicación. Native completion can replace it with Location not available / Ubicación no disponible. ProductionMap and the separate ClaimVenuePicker construct this native subclass with the original position options and tracking disabled. Existing locale-dependent lifecycle replaces the control when language changes. No vendor patch, observer, polling, additional GPS call or listener is added.

`tests/map-geolocation.test.ts` evaluates the actual installed production/development/CSP/CSP-development bundles in an inert DOM. All 56 cases pass: exact unmodified baseline, both locales pending, granted state, real native click into permission-denied error, denied availability, unsupported API, rejected Permissions query fallback, removal before settlement and locale replacement. Initial disabled clicks perform zero position/watch calls. Removal retains native listener cleanup. This proves native control behavior without claiming WebGL, physical browser/device or production geolocation acceptance. The file is wired into the existing default npm test command. The separate 29 attribution/backport checks and fingerprint gate remain required.
