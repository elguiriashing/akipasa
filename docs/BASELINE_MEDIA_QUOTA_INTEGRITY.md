# Baseline media quota integrity

The base listing limits and enhanced media library have separate rollout gates. Before this amendment, `guard_library_placement` returned immediately while `library_enabled=false`. A target venue member could associate nine public foreign images while owning no images; neither the base image registration count nor the library-disabled Storage count saw those images. Existing historical cross-listing placements were also excluded from the verified reservation wrapper whenever the enhanced library was disabled.

The additive `20261021190000` migration requires the independent `181500` quota serialization migration. It preserves installed function owners, ACLs, OIDs, security configuration and authorization bodies, replacing only exact canonical count queries and the library-only reservation early return. Unknown versions abort the transaction. It changes no flags, subscriptions, ownership, files or existing rows.

A private shared count deduplicates actual storage paths across owned media, historical shared placements, venue Storage objects and unexpired pending/uploaded reservations. All of these consume the existing 8/250 image and approved existing byte allowances whether or not the enhanced library is enabled. New media registration also checks this aggregate; existing own-media, stored-byte validation and membership checks remain. Reservation and Storage operations retain the existing advisory and revision-row locks, including repeatable-read serialization.

When base enforcement is active but the enhanced library remains disabled, new or changed cross-listing media associations are rejected. Existing associations remain readable, removable and editable without changing the asset or destination; ordinary same-listing placement remains available. When the enhanced library is enabled, its existing scoped source/target authorization and Premium reuse rules continue to apply. This guard does not expose or launch the enhanced library early.

Validation: eight role-level SQL regressions reproduce the pre-fix nine-image bypass and verify rejection, retained historical data, registration metadata, raw Storage admission, verified reservation accounting, eight-image boundary, pending reservation accounting after strict-upload rollback, private helper grants, disabled cohorts, and licensed enhanced-library reuse. The isolated real PostgreSQL race job also exercises shared-only historical assets under READ COMMITTED and REPEATABLE READ, in addition to existing event, own-upload and reservation cases. Its exact hosted result must be recorded before merge; local PGlite tests do not establish multi-session PostgreSQL behavior.

Rollout: root must review and apply `181500` then this forward migration before enabling base listing enforcement. Existing global `enabled`, `uploads_enforced` and `library_enabled` gates remain unchanged. The strict upload and enhanced library launch still require the separately documented actual provider byte-upload acceptance. To roll back a launch, disable `library_enabled` before `uploads_enforced`, respecting the existing database invariant; disabling base enforcement retains every historical asset. Do not replay or edit previously applied migrations to roll this fix back.
